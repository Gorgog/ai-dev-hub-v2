## What

Две сессии проекта гоняют тесты одновременно, не мешая друг другу и не стоя в очереди за общей тестовой БД.
При создании worktree скрипт хаба создаёт БД из шаблона в уже существующем тестовом контейнере проекта;
обёртка запуска тестов подставляет её адрес переменной окружения; при удалении worktree БД удаляется. Всё,
что нужно знать о проекте (контейнер, шаблон, имя переменной, команда тестов), — в его локальном профиле
хаба. В репозитории клиентского проекта — ноль изменений, туда ничего не пушится (Georgy 05.11).

## How

- Размер: M (калибровочно). Поток S, волна 3.
- Касания: `plugin/skills/dispatch/scripts/` (`wt-new.sh`, `wt-remove.sh`, новая обёртка запуска тестов),
  `dispatch/SKILL.md` §4, шаблон профиля проекта (`templates/project/dispatch-profile.md`), запись реестра;
  горячие точки: `dispatch/SKILL.md` и шаблон профиля (после 17, до 18).
- Проба P4 — первым шагом, в песочнице (синтетический проект с тестовым контейнером в `~/hub-data/sandbox/`,
  ничего общего с рабочими клонами): берут ли тесты адрес из env или его перекрывает `.env.test`, хватает
  ли подключений (`max_connections`), пик RAM двух прогонов, время создания БД из шаблона.
- Перекрывает `.env.test` → обёртка подаёт адрес способом, который проект не перекрывает (по профилю), без
  правки файлов проекта; не получается без правки — стоп, вопрос Georgy.
- Уборка: БД удаляется вместе с worktree (`wt-remove.sh`); осиротевшие БД (worktree удалён мимо скрипта)
  находит проверка на SessionStart проекта.
- После 26 — замер очереди тяжёлого (скрипт среза 02); он решает, нужен ли срез 18.
- Prior art: `wt-new.sh` / `wt-remove.sh` (создание и уборка worktree), `hub-run.sh` (обёртка запуска).
