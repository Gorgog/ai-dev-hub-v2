## What

Память проектов v1 (≈730 записей ошибок, ≈200 решений, рецепты) превращается в уроки и решения v2
детерминированным скриптом по файлу соответствия. Повторный прогон на том же снимке даёт тот же результат
побайтно; при переходе проектов скрипт прогоняется на доснимке. Память v1 не меняется.

## How

- Размер: M (калибровочно; P6 даёт время на тему — пересчитать). Поток S, волна 2.
- Касания: `tools/migrate-memory/` (скрипт, схема файла соответствия); данные — `~/hub-data/` и временный
  каталог вывода; горячие точки: нет.
- Файл соответствия (запись → урок/слияние/архив с причиной) готовит агент; проверка — детерминированный
  якорь (хэши всех исходных записей отображены, сирот 0) и независимая сессия по определению
  `acceptance.md` §5; пограничное — Georgy.
- `source` у мигрированных уроков — «модель (миграция)», внешнего текста среди них быть не может; класс
  «одного раза» — помечается, в отставку не идёт. Остатки Windows и дубли правил в заметках — в архив с
  причиной.
- Решения: второй регрессионный набор — 15–20 вопросов «почему так решили» с ответами по `decisions`.
- Вывод проходит валидатор библиотеки памяти (срез 12).
- Prior art: `parse_lessons.py` прототипа, `cases.json` набора 32.
